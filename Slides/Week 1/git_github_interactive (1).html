Git & GitHub

// Master version control — track every change, collaborate with anyone, deploy from anywhere.

🔴
Git
Local version control tool

A command-line tool that lives on your computer. It tracks every change you make to your files and lets you travel back in time to any previous version.

terminal
$ git init my-project
Initialized empty Git repository in my-project/.git/
🟣
GitHub
Cloud hosting for Git repos

A website (github.com) that stores your Git repositories online. It adds collaboration features like Pull Requests, Issues, and code review.

Key insight: Git ≠ GitHub. Git is the tool. GitHub is the website. You can use Git without GitHub — but not the other way around.
💡
Why Version Control?
The problems it solves
📸
Snapshot History
Never lose work. Every commit is a permanent save point you can return to at any time.
👥
Collaboration
10 developers, same codebase. Git merges everyone's work without overwriting each other.
🌿
Safe Experiments
Create a branch to try something risky. If it breaks, delete the branch. Main code is untouched.

The Pull Request Workflow
How open source collaboration works
1
Fork the repository
Click Fork on GitHub to create your personal copy of someone else's repo.
github.com → Fork button
2
Clone your fork
Download your fork to your local machine so you can make changes.
git clone https://github.com/you/repo.git
3
Create a feature branch
Never work directly on main. Create a named branch for your change.
git checkout -b feature/my-improvement
4
Commit your changes
Make your edits, stage them, and commit with a clear message.
git add . && git commit -m "Add feature X"
5
Push and open Pull Request
Push your branch to GitHub, then click "New Pull Request" to propose your changes.
git push origin feature/my-improvement
6
Review, discuss, merge
The repo owner reviews your PR, may request changes, then merges it if approved.
github.com → Merge Pull Request

Reference
Ways to Refer to a Commit
Whenever a Git command accepts a <commit>, you can use any of these shorthands.
🏷️
Commit Reference Syntax
Every <commit> slot in Git accepts any of these
main
A branch name — points to the latest commit on that branch
v1.0.0
A tag name — a named pointer to a specific commit
3e887ab
A commit hash (can be abbreviated to 7+ chars)
origin/main
A remote tracking branch — the remote's last known state
HEAD
The current commit — whatever branch/commit you are on now
HEAD~3 or HEAD^^^
3 commits before HEAD. HEAD~1 = parent, HEAD~2 = grandparent
HEAD^2
The second parent of a merge commit (for merge commits only)
branch@{3}
The 3rd previous position of a branch (from reflog)
examples using commit references
# All of these are valid ways to reference commits:
$ git show HEAD # show the latest commit
$ git show HEAD~3 # show 3 commits ago
$ git diff HEAD~5 HEAD # diff: 5 commits ago vs now
$ git diff main feature/login # diff two branches
$ git checkout v1.0.0 # go to a specific tag
$ git reset --soft HEAD~1 # undo last commit
$ git reset --hard origin/main # reset to remote state
Tip: HEAD is just a file in .git/HEAD that contains the name of the current branch (or a commit hash in "detached HEAD" mode). Understanding HEAD unlocks every advanced Git operation.
